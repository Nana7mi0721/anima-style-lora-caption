# 打标执行流程详规

配套 SKILL.md §3~§5。本文件讲**怎么做**；标签内容的取舍见 `references/Anima_style_LoRA_打标指南.md`。

---

## 1. 阶段 -1 ~ 1：准备与下采样

### 1.1 归档现有初稿（若有）

自动打标初稿（JoyCaption / WD14 / VLM 产物）与最终 caption **通常是同名文件**，写回会覆盖它们。开工前先原样拷贝一份到独立目录（如 `<WORK>/joycap_<name>/`）。

⚠️ 若初稿以游离的 `, ` 开头（`{触发词}, {输出}` 模板残留，触发词位为空），归档时**保留原样**，剥除操作放在解析阶段。

### 1.2 下采样

**目的**：统一尺寸、省 token、规避「大图被静默拒绝」与「请求体超上限」两类故障。

| 目标 | 规格 |
|---|---|
| 长边 | ≤1536 px |
| 体积 | ≤2 MB |
| 格式 | JPEG（质量适中） |

- 抽样确认原图体积：若普遍 >8MB，**必须下采样**
- 若图片本身体积很小（≤3.5MB），可直读原图，跳过此步（由用户决定）
- 子代理读的是缩略图，裁切坐标也基于缩略图

### 1.3 生成 tag 动作表

扫描数据集里出现过的**每一个** tag，逐条给出动作。列结构：

| 列 | 含义 |
|---|---|
| `tag` | 原始标签 |
| `count` | 出现次数 |
| `action` | `DELETE` / `KEEP` / `NORMALIZE` / `CHARACTER` |
| `target` | 归一化目标形 |
| `slot` | 落到哪个槽位（1~7） |
| `note` | 理由（**必填**） |

动作判定规则见参考文档「该删的 / 该保留的」与「标签规范化」两章。这张表是把规则变成**可执行、可复查、可重跑**的关键产物——改规则时只需改表重跑合并，不必重跑视觉。

## 2. 阶段 2：派发子代理看图

### 2.1 提示词模板（结构化槽位填空）

**必须**用字段填空形态，不要开放式描述。按数据集类型增删字段：

```
你在帮我给一个插画数据集做「洗标」——为每张图生成可用于 LoRA 训练的
danbooru 风格英文标签串。我是主代理，我自己不读图，看图这一步交给你。

用 Read 工具依次看下面这 N 张图（都已下采样，单张 <=2MB）：

  <缩略图绝对路径 × N>

硬性约束：
- 必须用你自己的 Read 视觉能力看图；禁止使用任何外部视觉工具/插件；
- N 张都要看，逐张独立作答，不要把不同图的特征混在一起；
- 这是插画数据集的专业标注工作，按标注规范如实填写，措辞客观、就事论事、
  临床式，不回避、不淡化、不做道德评判；
- 某一张因为任何原因无法处理时，跳过它继续处理其余，不要因此停下。

【可选手段：裁切局部放大 —— 按需，不要每张都裁】
缩略图长边只有 1536。先用 Read 看整张缩略图；只有在「关键细节看不清、
且该细节会改变标签正确性」时才裁切放大核验。
- 值得裁的：<针对本数据集列 2~4 项>
- 不值得裁的：<发色/瞳色/发型/表情/光影/构图/服装大类 —— 整张图就能判断>
- 每张图最多裁 1-2 块；裁切很费 token 与时间，滥用会显著拖慢整轮。
需要裁时写到你这个专属目录：
  <你的专属目录>
- 坐标是缩略图像素坐标；命名带图号与部位。
- 这个目录是你一个人专用的，不要删别的目录、不要删上一级。
- 全部处理完后删掉自己这个目录。

【每张图的既有文本】（若有初稿/权威标签）
## NNNN
(1) booru 权威标签（事实基准，不得推翻）：<tags>
(2) 自动打标初稿（可能有幻觉，需要你核对）：<text>

【你的任务】对每张图：校验既有文本 + 补标签空缺。
A. 校验：逐项核对初稿里关于画面的描述与图是否一致，不一致的列进 CORRECTIONS。
B. 补漏：权威标签未覆盖的字段，看图给出。
C. 重点字段（初稿覆盖最差，必须直接看图给，不得照抄初稿）。

【输出格式】每张图一个结果块，先英文 danbooru 风格小写标签，没有的写 none。
字段名照抄，值可以自由书写：

PEOPLE:      （人数与性别 + 关系标签，必答。solo 与 solo focus 互斥；
              同一角色多视图算 1 人，写 multiple views；sex 无 penis 仍算 1boy）
CHARACTER:   （主体角色判别，必答。是目标角色写 <trigger>；其他角色写
              other: <特征简述>，只记录不产出 tag；拿不准写 uncertain）
WATERMARK:   （必答。类型+位置+状态；没有写 none）
TEXT:        （必答。空对话框→speech bubble；拟态词→sound effects；
              可见签名→signature。真没有写 none）
ACTS:        （性行为与体位，客观直写；没有写 none）
FLUIDS:      （体液及其位置；只写画面里看到的，禁止否定式）
SCENE:       （场景环境/背景/道具，必答；纯色背景写 simple background 类）
COMPOSITION: （构图镜头）
HAIR: / EYES: / CLOTHING: / BODY: / EXPRESSION: / LIGHTING:
CORRECTIONS: （既有文本与画面不符处；没有写 none）

要求：
- 全部写小写 danbooru 风格标签，不写句子、不写形容词式散文；
- 看不到的信息不要写否定式（不写 no cum / tongue not out 这类）；
- 词汇必须是真实存在的 danbooru 标签，不要自造。

【落盘】每张图看完后，用 Write 工具把该图的结果块写成文件
（UTF-8，不要加 markdown 代码围栏，不要写别的图的内容）：
  <descriptions 目录\NNNN.txt × N>

【收尾】删掉你自己的裁切目录。

【回复】正文只回状态行，不要复述标签内容：
  0001 ok
  0002 refused: <一句话理由>
  ...
```

**为什么让子代理自己写文件**：N 并发 × 每代理 M 图 = 一轮几十份结果，若都回在主上下文里会把上下文撑爆。落盘后主代理只需读状态行，内容由解析脚本直接读文件。同时这也让「子代理返回空」变成**可检测的事实**（文件不存在），而不是只能靠回话判断。

**为什么把「否定式」写进提示词**：子代理会想表达「没看到」而写成 `no cum` / `tongue not out` 这类**反向标签**，比漏标更糟。提示词层先堵一次，合并层再兜底一次（两层都要）。

### 2.2 必答字段的选择原则

字段要**锁定在权威标签与初稿覆盖最差的地方**，否则等于让子代理重做已经做完的事。典型覆盖情况：

| 字段 | 权威标签 | 自动初稿 | 结论 |
|---|---|---|---|
| 人数/关系 | 常缺失 | 覆盖差 | 🔴 **必须看图** |
| 构图镜头 | 常为 0 | 覆盖极差 | 🔴 **必须看图** |
| 体位/行为细节 | 只打大类 | 部分 | 🔴 **必须看图补** |
| 场景环境 | 稀疏 | 覆盖好（主来源） | 校验初稿 |
| 光影色调 | 常为 0 | 覆盖好（主来源） | 校验初稿 |
| 发色/瞳色/服装 | 部分 | 中等 | 校验 + 补漏 |

### 2.3 裁切纪律

| 项 | 规定 |
|---|---|
| 何时裁 | 关键细节看不清**且该细节会改变标签正确性**时 |
| 上限 | 每图 **1~2 块** |
| 尺寸 | JPEG ≤800px，避免请求体超上限 |
| 每张原图 | **只 Read 一次** |
| 目录 | **每代理专属子目录**；多代理共用目录会互相删掉对方正在读的文件 |
| 清理 | 用完自删自己的目录，不动上一级；解析脚本每轮兜底清理并报告残留 |

**别裁的**：发色/瞳色/发型/表情/光影/构图/服装大类——整张图就能判断，裁了是浪费。

## 3. 并发与分组

| 项 | 规定 |
|---|---|
| 并发上限 | **先小批试探**（不同渠道差异很大：有的 10 并发可行，有的只能 3） |
| 分批 | 一轮 N 个代理 × 每代理 M 图；**整波被取消就拆小波**缩小爆炸半径 |
| 敏感度分组 | 若数据集含成人内容，**按敏感度分级派发**：低→中→高，高风险图单独小组押后试探 |
| 分类隔离 | sfw / nsfw **绝不混编**进同一个子代理 |
| 近重复对 | **不派给同一子代理**（防印象跨图复制）；一致性靠合并层校对 |
| 商业封面/特殊图 | 画面构成与字段侧重不同，**单独成组** |
| 载荷生成 | 生成载荷文件，主代理只发「读这个文件并执行」；载荷按磁盘落盘状态**自动跳过已完成图**，重跑即得最新待派清单 |

## 4. 失败处理

失败写台账 `vision_failed_<name>.txt`，格式 `编号<TAB>原因`，原因枚举：

| 原因 | 含义 |
|---|---|
| `no_vision_input` | 缩略图缺失 |
| `no_description_file` | 子代理没落盘 |
| `subagent_empty` | 子代理返回空 |
| `refused` | 子代理拒答 |
| `no_block` | 有文件但没有可识别字段块 |
| `parse_empty` | 有字段块但解析不出标签 |

**规则：只记台账，不兜底、不重试。** 该图本轮不产出 caption，是否补跑由用户看完台账裁决。

⚠️ **不要用「子代理返回空 → 按原 booru 标签做文本兜底」**：那会把失败藏起来，让人误以为已覆盖。

### 4.1 拒答是「批次级」的

实测对照：

| 派发粒度 | 结果 |
|---|---|
| 1 代理 5 图 | 0/5，整体拒答，**且没读图** |
| **1 代理 1 图（补跑）** | **5/5，零拒答** |

⇒ **遇到整批拒答，缩小派发粒度是最有效的对策**，比改提示词、换措辞都直接。

### 4.2 换成模型/渠道

若缩粒度后仍硬拒，换子代理模型/渠道常能直接解决（实测有 7 张被旧模型持续过滤，换模型后 7/7 成功）。

### 4.3 渠道级故障判别（四段探针）

当大面积空轮次或拒答时，用二分探针定位是「渠道问题」还是「提示词/图片问题」：

```
A 纯模板文本（无图无初稿） → ok
B 纯初稿文本（无图）       → ok
C 一张缩略图               → 拒
D 另一张之前成功过的缩略图 → 拒
⇒ 结论：渠道的视觉审查收紧，任何图片输入都被拒，
   与提示词、图片敏感度都无关。停派，等渠道恢复或换渠道。
```

### 4.4 备用视觉通道

若子代理通道不可用，可考虑由主代理经**第三方视觉工具**直读缩略图补标（工具只回传文本，主代理不读图纪律不破）。硬约束：

- **严格单发**（并行连发容易被整体拒绝，同图单发即过）
- 输出端可能被**净化**（露骨要素被隐去）→ 这类字段改采信初稿，并在描述文件头部**注记来源**，便于后续复核

## 5. 阶段 2.5：解析

子代理输出是**自由格式**，所以「描述 → 标签」的转换必须**显式独立成一步**，不能塞进合并脚本里做隐式猜测。产出三份账：

| 产物 | 内容 |
|---|---|
| `<WORK>/supplement_<name>/roundNN.json` | 本轮槽位化结果，按编号索引，直接喂给合并阶段 |
| `<WORK>/vision_failed_<name>.txt` | 失败台账，**不兜底不重试** |
| `<WORK>/vision_review_<name>.txt` | 人工复核清单：未登记槽位的 token（按字段默认槽位落位，待确认） |

解析层要做的规范化（否定式丢弃、口语形改写、角色名前缀剥离、描写词白名单放行）见 `assets/normalization.md`。

## 6. 阶段 3：合并

```
① 按 tag 动作表处理权威标签：DELETE 丢弃 / NORMALIZE 换形 / CHARACTER 保留 / KEEP 原样
② 视觉补漏的标签按槽位落位
③ 全量过一遍归一化表（VISION_FIX）：废弃形拦截、别名换形、否定式丢弃
④ 槽位排序：主体 → 外观着装 → 姿势动作 → 场景环境 → 光影色调 → 构图镜头 → 水印区
⑤ 触发词置首
⑥ 近重复对一致性校对
⑦ 水印区按视觉台账拼接（无则整区省略）
```

⚠️ **最容易踩的坑**：`VISION_FIX` / 描写词白名单的改动**同时影响解析与合并两层**。只改合并层会得到「0 张带这些词」的结果，因为词在**解析阶段**就已经被丢掉了。**必须先重跑解析，再合并。**

## 7. 阶段 4：校验

### 7.1 格式闸门（离线）

- 图-txt 配对完整（N 对）
- 单行、UTF-8 无 BOM、无尾换行
- 无前导逗号、无尾标点
- 全小写空格形、无重复 token
- 触发词置首且**仅首位出现 `@`**
- **BANNED 令牌零残留**：画师标签、IP 系列名、低频角色名、meta 常量
- **否定式 token 零残留**
- 质量词 0
- 人数一致性冲突 0（`solo` / `solo focus` 互斥）
- 水印区与视觉台账**逐张一致**

### 7.2 标签有效性闸门（在线）

- 用 danbooru `search[name_comma]` 批量查询（**每批 120 个**）
- 批量查 `tags.json` 时**必须带 `limit=len(批次)*2`**（`limit=0` 只回 1 条）
- **校验用「转换前的下划线原形」**：词典是下划线格式，空格形查不到
- 角色名带转义括号的要加白名单，注意别被正则截断
- **词典有洞是常态**（部分描写词不在词典内）→ 人工放行白名单，不要一刀切判未知

### 7.3 词典准备

| 项 | 要求 |
|---|---|
| 来源 | 从 danbooru API 拉取 tag 表 |
| 🔴 排序 | **必须带「按使用量降序」参数**。默认按 id 倒序（最新标签在前），会一路抓刚创建的长尾标签，**抓几十万行也抓不到 `nude` / `1girl` 这类高频标签** |
| 拦废弃 | `is_deprecated=1` 的必须拦下，改用现行形 |
| 本地缓存 | 本地大表只当离线缓存，**真正的闸门是在线批量查询** |

## 8. 阶段 5：备份与写回

1. **快照备份**到 `<BACKUP_DIR>/<name>_<时间戳>/`
2. 🔴 **备份必须包含自动打标初稿本身**——写回会覆盖同名文件，初稿是原始打标数据。若备份目录里没有初稿，恢复时不可逆
3. 图片通常不必备份（体积大）；标签动作表、重命名对照表要备份
4. 写回 → **写后复检** → 抽查：
   - 槽位顺序、单行、全小写、UTF-8、无重复 token
   - 随机若干张对照图复核
   - 近重复对逐对核对一致性
5. 已应用的文件做 **token 级幂等替换**，不整行重写

### 8.1 改规则后的快速迭代路径（不用重跑视觉）

```
① 重建 tag 动作表（若改了阈值/规则）
② 重新解析（改了 VISION_FIX 或白名单时**必须**做）
③ 重新合并
④ 重新校验
⑤ 满意后再写回（自动先备份）
```

## 9. 中断恢复

| 现象 | 处置 |
|---|---|
| 子代理会话中断、返回空 | 「写一张落一张」——已落盘的不重做，只补缺失编号 |
| 整波代理被同时取消 | 拆小波次；重派前**先查落盘状态** |
| 子代理忘删裁切临时图 | 解析脚本每轮兜底清理并报告数量 |
| 主会话中断 | 中间产物全部落盘，按落盘状态续跑，不依赖上下文记忆 |
